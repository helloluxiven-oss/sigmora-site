Describe your business. Get a team of agents that runs it.

SIGMORA Agentic OS is a local-first desktop app that turns a plain-English description of your business into a working team of AI agents — a CEO agent that delegates to department heads and workers — which actually run your workflows and produce real deliverables: reports, plans and spreadsheets, on your own machine.

How it works

A real org, not one long chat.

A loop around a single model is one improviser doing everything in prose. SIGMORA runs a bounded tree of specialised agents, each with its own instructions, its own model, and only the tools it was granted.

Step one

You describe it

Describe your business in plain English. It generates a complete agent org — the roles, the delegation tree, starter workflows and a data plan.

An “Improve my org” advisor reads your real run history afterwards and proposes concrete changes.

Step two

It builds the org

An org is a tree of agent nodes: a lead orchestrator — the CEO — leading department heads for Marketing, Sales, Finance and the rest, which in turn lead workers.

Each node is a role, its own system instructions, a model, a tool allowlist, and its direct reports. Nothing is shared implicitly.

Step three

They do the work

Every manager holds a delegate tool scoped to its direct reports only. Calling it spawns a fresh, isolated run for that child, then returns the result to the parent. Results bubble up, and the lead synthesises the final answer.

Anything carrying a number is assembled by code, not the model — totals, metrics and tables are computed exactly. The model writes the prose around them.

It cannot run away
Hard caps on delegation depth, number of agent runs, total iterations, per-tool call budgets and wall-clock time. The clock is shared across the whole run, so one limit winds the entire tree down rather than leaving branches spinning.
You sign off on risk
Any risky or irreversible tool is wrapped in a human approval gate. It pauses and waits for you before it runs.
Everything is on the record
A full audit trail of every start, every delegation, every tool call and every result.
Why local-first

Private mode is a switch, not a promise.

Most tools ask you to trust a policy. This one is a desktop app, so the question of what leaves your machine has an answer you can enforce rather than a paragraph you have to believe.

It installs on your machine

A packaged desktop app that runs on your own hardware, alongside a web UI and a terminal client for the same engine.

Your knowledge base is a local Markdown vault — ordinary files in ordinary folders, on your disk, that your agents read from and write to.

Private mode forces every agent local

One toggle forces every agent — the lead and every worker under it — onto a local model, and blocks all cloud traffic. Not a default that a per-agent override can quietly undo.

Cloud models are bring-your-own-key and stay inert while it is on. Local models run through Ollama, with no key and no account.

Connectors are the surface that can reach outside, so they are the surface Private mode cuts off. Each one is MCP-backed: you register the server, choose which of its tools it grants, and attach it to the agents that should hold it. Nothing is connected by default. This list is generated from the product's own connector catalogue rather than written by hand, so the site cannot quietly claim an integration the app does not offer.

What people actually point it at.

Departments, workflows and automations an agent org can run. Three below; the rest are on the use-cases page.

Route the day's jobs and chase the exceptions

Operations agents watch the queue, escalate what's stuck, and post a single shift summary to Slack instead of a stream of separate pings.

Semantic search
Knowledge-vault retrieval is keyword and frontmatter based. It is not embeddings-based semantic search yet.
Headless background service
Scheduled workflows fire while the app is resident in your system tray. It is not a service that runs without it.
Multi-tenant enterprise layer
It is single-user and local today. There is no shared or multi-tenant deployment.
Native first-party integrations
Connectors are MCP servers you register yourself. SIGMORA does not ship its own OAuth clients for Gmail, Slack or Sheets.

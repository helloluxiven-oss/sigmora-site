How it works

A real org, not one long chat.

A loop around a single model is one improviser doing everything in prose. SIGMORA runs a bounded tree of specialised agents — each with its own instructions, its own model, and only the tools it was granted.

Describe

You describe it

In plain English. It generates a complete agent org — the roles, the delegation tree, starter workflows and a data plan.

Later, an “Improve my org” advisor reads your real run history and proposes concrete changes.

Build

It builds the org

A tree of agent nodes: a CEO leading department heads for Marketing, Sales, Finance and the rest, which in turn lead workers.

Each node has its own role, instructions, model, tool allowlist and direct reports. Nothing is shared implicitly.

Run

They do the work

Every manager holds a delegate tool scoped to its direct reports only. Each child runs fresh and isolated; results bubble up and the lead synthesises the answer.

Anything carrying a number is assembled by code, not the model — totals, metrics and tables are computed exactly.

Built with brakes.

Autonomy you can actually leave running.

It cannot run away

Hard caps on delegation depth, agent runs, iterations, per-tool call budgets and wall-clock time. The clock is shared across the whole run, so one limit winds the entire tree down.

You sign off on risk

Any risky or irreversible tool is wrapped in a human approval gate. It pauses and waits for you before it runs.

Everything is on the record

A full audit trail of every start, every delegation, every tool call and every result.

Why local-first

Private mode is a switch, not a promise.

Most tools ask you to trust a policy. This is a desktop app, so what leaves your machine has an answer you can enforce — not a paragraph you have to believe.

Private modeevery agent local

One toggle forces every agent local

The lead and every worker under it move onto a local model, and all cloud traffic is blocked. Not a default that a per-agent override can quietly undo.

Cloud models are bring-your-own-key and stay inert while it is on. Local models run through Ollama — no key, no account.

It installs on your machine

A packaged desktop app on your own hardware, alongside a web UI and a terminal client for the same engine.

Your knowledge base is a local Markdown vault — ordinary files in ordinary folders that your agents read from and write to.

Connectors — off until you turn them on

Connectors are the one surface that can reach outside, so they are what Private mode cuts off. Each is MCP-backed: you register the server, choose which tools it grants, and attach it to the agents that should hold it. This list is generated from the product's own connector catalogue, so the site cannot claim an integration the app does not offer.

Run it on your own work, while it is still being built.

There is no installer to download, so the honest version of “try it” is this: a small number of businesses run SIGMORA on their real workflows, and what they run into decides what gets built next.

Who it suits. Businesses with repetitive back-office work — finance ops, vendor management, reporting — where the same job comes round every week and somebody senior is still doing it by hand.

What you don't get
An SLA or a support guarantee
This is a product under construction. When something breaks there is no queue to escalate to — only the person who wrote it.
Settled pricing
Nothing is being sold here. What this costs, if anything, is a conversation for when there is something to install.
A stable product underneath you
Interfaces, defaults and whole features will change while you are using it. You get to shape them, and you carry the churn.
